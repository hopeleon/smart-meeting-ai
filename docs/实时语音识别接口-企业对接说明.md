# 实时语音识别接口 · 企业对接说明

## 一、概述

本服务提供**实时流式语音识别**(边说边出字 + 说话人分离/识别)。

> 实时流式音频**必须用 WebSocket**(持续推流、持续返回);REST/HTTP POST 是"请求-响应",做不到真正的边说边出字,只适合"上传完整录音→返回整段转写"。本说明针对**实时模式**,采用 WebSocket。

提供三种识别模式,任选其一:

| 模式 | 端点后缀 | 特点 | 建议场景 |
|---|---|---|---|
| **FunASR** | `/funasr` | 中文专用、抗噪、低延迟 | 嘈杂/口音会议 |
| **Whisper** | `/whisper` | large-v3,**转录最准**、漏字最少 | 追求转录质量 |
| **Qwen** | `/qwen` | 近实时、均衡、说话人分离最稳 | 综合推荐 |

---

## 二、连接信息

- **服务地址**:`ws://<服务器IP>:8020`(示例:`ws://183.36.243.124:8020`)
- **端点路径**:
  - FunASR:`ws://<IP>:8020/ws/meeting/{会话ID}/funasr`
  - Whisper:`ws://<IP>:8020/ws/meeting/{会话ID}/whisper`
  - Qwen:`ws://<IP>:8020/ws/meeting/{会话ID}/qwen`
- **{会话ID}**:由调用方自行生成的唯一字符串(建议用 UUID),用于区分不同通话/会议。每路通话用一个新的会话ID、一个新的 WebSocket 连接。

> 如需 HTTPS/WSS,请使用 `wss://<IP>:<安全端口>`(由部署方提供)。

---

## 三、音频格式(重要)

推送的音频必须是:

| 项 | 要求 |
|---|---|
| 编码 | PCM(原始裸流,**不要** wav 头、不要 mp3/opus) |
| 采样位深 | 16-bit 有符号整数(int16),小端(little-endian) |
| 采样率 | **16000 Hz** |
| 声道 | **单声道(mono)** |

- 按小帧持续发送(建议每帧 **20~100ms**,即 640~3200 字节)。
- 麦克风/其它采样率的音频,需在客户端**先重采样到 16kHz 单声道 int16** 再发送。

---

## 四、消息协议

### 客户端 → 服务端
- **二进制帧**:PCM 音频数据(按上面的格式)。
- **空二进制帧 `b""`**:表示音频流结束(可选,优雅收尾用)。

### 服务端 → 客户端(均为 JSON 文本帧)

| `type` | 含义 | 主要字段 |
|---|---|---|
| `config` | 连接建立确认 | (无需处理) |
| `transcript.completed` | **一句转写结果** | 见下表 |
| `ready_to_stop` | 服务端已收尾,可断开 | — |

`transcript.completed` 字段:

| 字段 | 类型 | 说明 |
|---|---|---|
| `text` | string | 转写文本 |
| `speaker_id` | string | 说话人标识(已识别=真名/库ID;未识别=`speaker_1`等匿名) |
| `speaker_name` | string | 展示名(同上) |
| `identified` | bool | 是否在声纹库中确认了身份 |
| `best_guess_name` | string\|null | 最高分候选(即使未达确认阈值) |
| `start_ms` / `end_ms` | int | 该句在音频流中的起止毫秒 |
| `start_time` / `end_time` | float | 起止秒 |

> 说话人**身份识别**依赖服务端声纹库已注册该人;未注册者会以匿名 `speaker_N` 区分。

## 五、Python 客户端示例(完整可运行)

```python
# pip install websockets
import asyncio, json, uuid, wave, websockets

async def transcribe(wav_path, host="183.36.243.124", port=8020, mode="qwen"):
    """mode: 'funasr' | 'whisper' | 'qwen'"""
    sid = uuid.uuid4().hex
    suffix = "" if mode == "funasr" else f"/{mode}"
    url = f"ws://{host}:{port}/ws/meeting/{sid}{suffix}"

    wf = wave.open(wav_path, "rb")
    assert wf.getframerate() == 16000 and wf.getnchannels() == 1 and wf.getsampwidth() == 2, \
        "音频必须是 16kHz / 单声道 / 16-bit PCM"

    async with websockets.connect(url, max_size=None) as ws:
        async def sender():
            while True:
                data = wf.readframes(1600)   # 1600 样本 = 100ms
                if not data:
                    break
                await ws.send(data)          # 推送 PCM 帧
                await asyncio.sleep(0.1)      # 模拟实时节奏(真实采集时无需 sleep)
            await ws.send(b"")               # 通知结束

        async def receiver():
            async for msg in ws:
                d = json.loads(msg)
                if d.get("type") == "transcript.completed":
                    name = d.get("speaker_name") or d.get("speaker_id")
                    print(f"[{d['start_ms']/1000:6.1f}s] {name}: {d['text']}")
                elif d.get("type") == "ready_to_stop":
                    break

        await asyncio.gather(sender(), receiver())

if __name__ == "__main__":
    asyncio.run(transcribe("test_16k_mono.wav", mode="qwen"))
```

### 实时麦克风采集(要点)
真实场景不是读 wav,而是从麦克风/电话流持续拿 PCM:
- 用采集库(如 `sounddevice`、`pyaudio`)以 16kHz/mono/int16 采集;
- 每拿到一小段(20~100ms)就 `await ws.send(pcm_bytes)`,**不要 sleep**;
- 边发边在 `receiver` 里收 `transcript.completed` 实时展示。

---

## 六、注意事项

1. **一路通话 = 一个连接 = 一个会话ID**;多路并发就开多个连接(各自独立)。
2. **网络**:企业侧需能访问服务器 `<IP>:8020`(防火墙放行 / 端口映射 / 内网打通)。生产建议加 **WSS + 鉴权(Token)**,由部署方提供。
3. **延迟**:三种模式均为近实时;Whisper(large-v3)质量最高、延迟略大(秒级,在可接受范围)。
4. **Qwen 模式**需服务器侧的 Qwen-ASR 微服务(8030)已启动;FunASR/Whisper 无此依赖。
5. **返回是"逐句"**:服务端按语音停顿/说话人切换分句返回,`start_ms/end_ms` 可用于排序与对齐。

---

## 七、若企业更想要"上传录音文件→返回整段转写"(非实时)

这种**批量**场景才适合 REST POST。如有需要,可另行提供一个 `POST /api/transcribe`(上传音频文件 → 返回完整转写 JSON)接口与说明——请告知是否需要。
