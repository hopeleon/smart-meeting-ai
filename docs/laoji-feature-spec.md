# 老记：一句话代办与智能日历功能说明

更新时间：2026-07-03  
适用模块：`/laoji` 老记日程助手，接口命名空间为 `/api/laoji`  
当前定位：面向会议、办公和个人事务场景的语音优先型智能日程入口。

## 1. 功能定位

老记是一个“一句话创建日程”的智能代办模块。用户可以通过自然语言、麦克风录音或系统音频输入一句描述，例如“老记老记，下周三下午两点和周总开会，要讨论硬件相关问题”，系统会自动完成语音转写、时间理解、日程结构化、追问补全、冲突提示和日历写入。

它不是传统表单式日历，而是一个低摩擦的智能入口：用户先把事情说出来，系统再把自然语言压缩为可确认、可编辑、可保存的结构化日程。

## 2. 已实现能力

### 2.1 一句话自然语言创建

已支持用户输入一句完整或半完整的日程描述，系统自动抽取：

- 事件标题：例如“周总开会”“项目周报”“团队例会”
- 事件日期：支持今天、明天、后天、大后天、下周三、7月25日、月底、月底前、下月底等表达
- 开始时间：支持下午两点、上午九点半、14:30 等表达
- 结束时间：默认按开始时间顺延 1 小时
- 事件类型：一次、每天、每周、每月、每年
- 补充描述：例如“要讨论硬件相关问题”“带上预算表”“报销的事”
- 原始语音文本：保留用户原话，便于回溯
- 置信度与解析来源：区分规则解析、本地大模型解析和追问补全

### 2.2 规则解析 + 本地大模型混合解析

当前采用“高频规则优先，本地大模型兜底”的混合策略。

规则解析用于高确定性的常见口令，优点是快、稳定、可控，例如：

- “明天下午三点提醒我发项目周报”
- “每周一上午十点团队例会”
- “7月25日下午两点开会”
- “月底前找财务确认报销的事”

本地大模型用于更口语化、更复杂或更模糊的指令，例如：

- “下周找个时间和周总聊一下硬件预算”
- “本月内抽空整理一下项目材料”
- “月初把上个月报销和硬件预算一起过一下”

当前本地模型默认使用 `qwen3:8b`，用于结构化解析、语义理解和追问判断。32B 总结模型不作为老记默认链路，避免显存占用过高和响应延迟过长。

### 2.3 模糊时间追问

当系统识别到时间表达存在不确定性时，不会直接强行保存，而是进入追问确认状态。

典型触发条件：

- 截止型表达：月底前、年底前、之前、截至
- 模糊型表达：尽快、抽空、有空、找个时间、大概、左右
- 日期或时间缺失：只说了事项但没有明确时间

示例：

```text
老记老记，月底前找财务确认报销的事
```

系统会生成候选日程，并追问：

```text
没有听到具体时间，是否作为全天事项保存？
```

### 2.4 文本补充与语音补充

追问区域已支持两种补充方式：

- 手动输入补充：例如“7月25日下午三点”
- 语音输入补充：点击“语音补充”，直接说出补充信息

补充信息会应用到当前草稿，而不是重新开始一次解析。这样可以形成更自然的多轮体验：

```text
用户：月底前找财务确认报销的事
老记：没有听到具体时间，是否作为全天事项保存？
用户：7月25日下午三点
老记：更新为 2026-07-25 15:00-16:00
```

### 2.5 本地 FunASR 一次性转写与音频波形反馈

前端已从浏览器 Web Speech 改为更可控的本地一次性转写链路：

1. 浏览器采集麦克风或系统音频。
2. 前端将音频整理为 16kHz 单声道 WAV。
3. 调用后端 `/api/laoji/asr/transcribe`。
4. 后端复用本地 FunASR 完成中文转写。
5. 转写结果写入主输入框或追问补充框。

当前可区分两种转写目标：

- 一句话代办录音：写入主输入框
- 追问补充录音：写入补充回答框

波形区域同时展示：

- 麦克风或系统音频权限状态
- 当前是否检测到明显声音
- 录音、收尾、转写状态
- 当前转写目标
- 实时音量变化

为了降低 ASR 同音误识别对体验的影响，当前已内置老记唤醒词归一化：

```text
老纪 / 老计 / 老季 / 牢记 / 小记 -> 老记
```

例如 ASR 将“老记老记”识别为“老纪老纪”时，解析前会自动归一为“老记老记”。

### 2.6 系统音频测试入口

页面提供“系统音频”按钮，便于在本地麦克风不可用或远程 SSH 场景下测试 ASR。

使用要求：

- 页面需要通过 HTTPS 或可信 localhost 访问
- 浏览器共享屏幕或标签页时需要勾选共享音频
- 系统音频同样走 `/api/laoji/asr/transcribe`，不再走会议实时 WebSocket

这个入口主要用于测试音频链路、演示播放音频自动转写，以及规避本地麦克风驱动问题。

### 2.7 确认表单与日历写入

系统不会在解析后立即保存，而是先进入确认区。用户可修改：

- 标题
- 重复类型
- 日期
- 开始时间
- 结束时间
- 是否全天
- 补充描述

确认无误后点击“保存到日历”，后端写入 SQLite 日程库。

### 2.8 日历视图与日程列表

右侧月历支持日期选择和已有事件标记。左侧会展示当前选中日期的日程列表。

已支持重复事件动态展开：

- 每天
- 每周
- 每月
- 每年

例如“每周一上午十点团队例会”只保存一条重复规则，但在月视图中会展开到对应的每个周一。

### 2.9 冲突提示

当新草稿与已有日程在同一天或同一时间段存在重叠时，确认区会提示“这个时间附近已有安排”。

当前冲突判断策略：

- 全天事项与当天任意事项视为潜在冲突
- 有具体时间的事项按时间区间重叠判断
- 默认展示最多 3 条冲突项

当前策略是轻提示，不会阻止保存。

### 2.10 保存成功反馈与撤销

保存成功后，页面会给出绿色反馈，例如：

```text
已保存到 7月25日 周六 15:00 - 16:00
```

并提供“撤销”按钮，可快速删除刚保存的日程。

## 3. 当前接口

老记已经拆出独立接口前缀：`/api/laoji/*`。旧版 `/api/schedule/*` 暂时保留为兼容入口，避免已有脚本和页面立即失效。

独立轻量后端也已预留：

```bash
cd backend
ENV=local CORS_ORIGINS='["*"]' python3 -m uvicorn app.laoji.main:app --host 0.0.0.0 --port 8035
```

这个入口只挂载老记 API，不会在启动阶段预热会议实时转录、声纹或 WhisperLiveKit 模型。

### 3.1 文本解析

```http
POST /api/laoji/parse
```

请求：

```json
{
  "text": "老记老记，下周三下午两点和周总开会，要讨论硬件相关问题"
}
```

响应：

```json
{
  "title": "周总开会",
  "event_type": "once",
  "start_date": "2026-07-08",
  "start_time": "14:00",
  "end_time": "15:00",
  "is_all_day": false,
  "description": "硬件相关问题",
  "raw_text": "老记老记，下周三下午两点和周总开会，要讨论硬件相关问题",
  "parse_source": "rules",
  "confidence": 0.97,
  "needs_clarification": false,
  "clarification_question": null
}
```

### 3.2 追问补充

```http
POST /api/laoji/clarify
```

请求：

```json
{
  "current": {
    "title": "找财务",
    "event_type": "once",
    "start_date": "2026-07-31",
    "start_time": null,
    "end_time": null,
    "is_all_day": true,
    "description": "报销的事",
    "raw_text": "老记老记，月底前找财务确认报销的事",
    "parse_source": "rules",
    "confidence": 0.94,
    "needs_clarification": true,
    "clarification_question": "没有听到具体时间，是否作为全天事项保存？"
  },
  "answer": "7月25日下午三点"
}
```

响应：

```json
{
  "title": "找财务",
  "event_type": "once",
  "start_date": "2026-07-25",
  "start_time": "15:00",
  "end_time": "16:00",
  "is_all_day": false,
  "description": "报销的事",
  "raw_text": "老记老记，月底前找财务确认报销的事；补充：7月25日下午三点",
  "parse_source": "clarified",
  "confidence": 0.95,
  "needs_clarification": false,
  "clarification_question": null
}
```

### 3.3 一次性 ASR 转写

```http
POST /api/laoji/asr/transcribe
```

请求：

```json
{
  "audio_base64": "<base64 wav>",
  "filename": "laoji-command.wav"
}
```

响应：

```json
{
  "text": "老记老记月底前找财务确认报销的事。",
  "duration_sec": 7.96,
  "provider": "funasr"
}
```

说明：

- `audio_base64` 建议为 16kHz、16-bit、单声道 WAV。
- 返回文本已经做了老记唤醒词同音归一化。
- 当前接口用于老记短语音转写，不承担会议级长音频实时转录。

### 3.4 日程保存

```http
POST /api/laoji/events
```

用于将确认后的草稿写入日历。

### 3.5 日程查询

```http
GET /api/laoji/events?year=2026&month=7
```

用于查询指定月份事件，并动态展开重复日程。

## 5. 待实现与优化方向

### 5.1 独立轻量服务

当前已完成第一步拆分：老记拥有独立接口前缀 `/api/laoji`，并提供 `app.laoji.main` 轻量 FastAPI 入口。下一步建议继续把运行环境和前端外壳完全独立：

- 独立 FastAPI 应用
- 只加载短音频 FunASR、日程解析、日程存储和 Ollama 8B 调用
- 与会议转录、会议总结、声纹服务解耦
- 启动速度从几十秒降到几秒
- 方便后续做移动端或桌面端入口

这是当前最值得优先做的工程优化。

### 5.2 真正的多轮槽位追问

当前追问是“单次补充式”。下一步可以升级为槽位状态机：

- `title`：事项名称
- `date`：日期
- `time`：开始时间
- `duration`：持续时间
- `repeat`：重复规则
- `participant`：参与人
- `location`：地点
- `reminder`：提醒时间

系统每次只追问缺失或冲突最大的一个槽位，直到日程可保存。

### 5.3 提醒时间与事件时间分离

目前“提醒我发周报”会被处理为事件本身的时间。更高级的做法是拆分为：

- 事件发生时间
- 提醒触发时间
- 截止时间

例如：

```text
下周五前交材料，提前一天提醒我
```

应解析为：

- 截止时间：2026-07-10
- 提醒时间：2026-07-09
- 事项：交材料

### 5.4 更强的冲突处理

当前只做轻提示。后续可做主动建议：

- “这个时间已有团队例会，是否改到 15:30？”
- “当天已有 4 个安排，是否改到明天上午？”
- “这是全天事项，是否只设置为截止提醒？”

### 5.5 日程导出和系统日历同步

建议增加：

- ICS 文件导出
- CalDAV 对接
- 企业微信/飞书/Outlook/Google Calendar 同步
- 保存后推送提醒

### 5.6 人名、项目名和地点记忆

可建立轻量个人记忆库：

- 常用联系人：周总、张老师、财务
- 常用项目：硬件项目、周报、报销
- 常用地点：会议室 A、线上会议

后续解析时可提升标题和描述质量。

### 5.7 ASR 质量优化与热词机制

当前已支持本地一次性 ASR，但仍可继续增强：

- 增加热词或偏置词：老记、财务、报销、周总、硬件、周报
- 对短指令做端点检测，减少前后静音对转写速度的影响
- 在前端加入“上传音频测试”入口，便于排查浏览器采集问题
- 把短音频 ASR 独立成老记专用服务，避免会议 ASR 链路影响响应

## 6. 当前限制

- 默认部署仍与智能会议主服务共享进程；虽然已有 `app.laoji.main` 轻量入口，但还需要单独部署和前端代理配置。
- 本地大模型调用速度受显存、Ollama 队列和模型上下文影响。
- ASR 质量受音源、音量、噪声和浏览器采集方式影响；当前只做了常见老记唤醒词归一化。
- 系统音频采集依赖浏览器权限和共享音频选项，不同浏览器行为不完全一致。
- 模糊时间只支持部分硬编码追问规则。
- 冲突检测目前只在前端做轻提示，没有后端强约束。
- 重复规则尚未支持“每两周”“工作日”“每月最后一天”等复杂表达。
- 未实现提醒推送、外部日历同步和账号级多用户隔离。

## 7. 建议下一阶段优先级

1. 单独部署 `app.laoji.main`，让老记后端真正脱离会议主服务启动。
2. 将 `/laoji` 前端页面整理成 PWA 或独立 Web App 外壳。
3. 为短语音 ASR 增加热词、端点检测和上传音频测试入口。
4. 做槽位式多轮追问，让老记从“一次解析”升级为“对话式安排”。
5. 将提醒时间、截止时间、事件时间拆成独立字段。
6. 增强冲突检测，从提示升级为可选择的改期建议。
7. 接入外部日历或 ICS 导出，形成真实办公闭环。
