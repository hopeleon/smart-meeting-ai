评估对象：FunASR、Whisper、Qwen 三种实时 WebSocket 模式

1. 结论摘要

当前系统已经具备企业实时 ASR 对接的基本协议形态：WebSocket 长连接、二进制 PCM 推流、逐句 JSON 返回、会话 ID 隔离、三种识别模式入口。但从本轮环境启动和仓库既有评测结果看，距离企业稳定交付还差一层工程化收敛。
  • 协议方向正确：/ws/meeting/{id}/funasr、/whisper、/qwen 三种端点已与企业实时推流方式对齐。
  • 当前本地环境不可直接完成三模式在线验收：本轮启动中 FunASR ASR 模型加载失败，Qwen-ASR 微服务因无 CUDA 失败，健康检查无法稳定访问 8020/8030。
  • 历史客观评测显示：在 6 场合成中文会议上，Whisper 文本 CER 最低，Qwen 综合更稳，FunASR 说话人过分割最明显。
  • 企业推荐路线：优先把 Qwen 模式 打磨成默认推荐模式；保留 Whisper 作为高准确率/离线增强方案；FunASR 作为低延迟和中文抗噪备选。

3.3 模式解读

Qwen：中文实时综合表现最均衡，文本 CER 比 FunASR 低，说话人聚类比 FunASR 少过分割。短板是强依赖独立 Qwen-ASR 微服务和 CUDA。本轮环境无 GPU，因此不可用。建议作为企业默认主链路。

Whisper：历史评测中文本 CER 最低；配合 pyannote 时，说话人数量最接近真值。短板是该 CER 是批量上界，不等同实时流式表现，真实会议中还需处理繁体、方言标签、静音幻觉。

FunASR：中文专用、低延迟潜力好，适合资源较轻场景。但本轮模型未成功加载，历史评测中过分割最明显。

5. 优化路线建议

5.1 P0：先让企业验收链路稳定可跑

  1. 修复启动脚本端口检测：用 HTTP 轮询 /api/health 和 WebSocket 轻量握手替代 ss。
  2. 增加统一 readiness：建议新增 GET /api/asr/modes 和 GET /api/asr/health。
  3. 修复 Qwen 启动失败：启动前检查 CUDA/显存，无 GPU 时返回结构化 unavailable。
  4. 修复 FunASR 模型加载：固定本地模型路径，禁止生产启动时自动联网下载。
  5. 补企业鉴权和 WSS：支持 Token、会话限流、最大连接时长。

5.2 P1：建立可交付质量指标

  1. 编写三模式统一测试脚本，输出首包延迟、最终延迟、断连次数、错误事件。
  2. 增加真实会议测试集：噪声、混响、抢话、远场麦克风、电话窄带、口音。
  3. 补 DER 和身份识别准确率。
  4. 做 1/5/10/20 路并发压测。
  5. 统一错误协议，例如 MODEL_UNAVAILABLE、BAD_AUDIO_FORMAT、SESSION_LIMIT_EXCEEDED。
