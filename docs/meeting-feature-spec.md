# 智能会议记录功能说明

更新时间：2026-07-03  
适用模块：会议列表、实时会议、离线转写、说话人管理、会议总结与导出  
当前定位：面向企业会议场景的实时语音记录与会后知识整理系统。

## 1. 功能定位

智能会议记录用于把会议音频转成结构化会议资产。它覆盖从会议创建、实时转写、说话人识别、阶段总结、最终总结到文档导出的完整链路。

系统目前更适合作为企业实时 ASR 和会议总结能力的验证平台。后续如果要进入稳定交付，需要继续补齐队列化总结、稳定的说话人分离、权限控制、日志监控和企业部署规范。

## 2. 已实现能力

### 2.1 会议创建与会议列表

前端支持创建会议、进入实时会议页、查看历史会议和会议详情。会议数据由后端 FastAPI 写入本地数据库。

主要页面：

- `/`：会议列表与入口页
- `/meeting/:id/active`：默认实时会议页
- `/meeting/:id/qwen`：Qwen ASR 实时模式页
- `/meeting/:id/whisper`：Whisper/FunASR 相关实验页
- `/meeting/:id/offline`：离线音频转写页
- `/meeting/:id/summary`：会议总结与导出页
- `/speakers`：声纹和说话人管理页

### 2.2 实时语音转写

系统已验证三类实时转写路线：

| 模式 | 作用 | 当前判断 |
| --- | --- | --- |
| FunASR 实时模式 | 负责低延迟字幕和会议过程记录 | 适合作为实时主链路 |
| Qwen ASR 模式 | 负责更强语义理解和句段修正 | 单独实时使用成本偏高 |
| FunASR + Qwen 混合模式 | FunASR 先出实时文本，Qwen 在句段级做增强 | 推荐作为企业化方向 |

推荐策略是：FunASR 保证会议现场的实时反馈，Qwen 在较高延迟容忍范围内做上下文修正、术语补全、句段润色和后续总结。

### 2.3 说话人识别与声纹管理

系统包含声纹管理入口，可以维护说话人身份，并在会议转写中尝试绑定发言人。当前状态更偏实验能力，仍需要在多人会议、噪声环境、多人重叠说话时继续增强。

已覆盖能力：

- 说话人列表管理
- 发言片段绑定说话人
- 转写项展示说话人名称
- 声纹相关测试数据已从仓库清理；如需回归测试，应从外部数据盘重新挂载测试样本

后续建议：

- 增加声纹注册和验证流程
- 对短句、插话、多人重叠说话做单独评测
- 在前端允许人工修正说话人，并把修正结果反哺声纹库

### 2.4 会议总结

系统支持最终总结展示和总结文档下载。会议总结可复用本地 Qwen 模型或外部 LLM 服务。

当前已发现的问题是：本地大模型总结在长上下文或 GPU 被占用时会比较慢，前端缺少足够细的进度反馈。建议下一阶段把总结改造成异步任务：

- 提交总结任务后立即返回任务 ID
- 前端轮询或 WebSocket 获取进度
- 按“转写清洗、段落聚合、摘要生成、行动项提取、文档生成”展示阶段
- 允许取消任务或切换更小模型

### 2.5 文档导出

会议详情页提供转写文档和总结文档下载入口。导出的内容适合后续归档、发给参会人或作为会议纪要初稿。

建议继续增强：

- 导出 DOCX/PDF/Markdown 多格式
- 保留说话人、时间戳、行动项、决议、风险点
- 支持企业模板，例如项目周会、评审会、需求会、复盘会

## 3. 后端接口概览

主要接口命名空间：

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| REST | `/api/meetings` | 会议创建、列表、详情和更新 |
| REST | `/api/meetings/{id}/transcripts` | 会议转写结果 |
| REST | `/api/meetings/{id}/summaries/*` | 阶段总结和最终总结 |
| REST | `/api/speakers` | 说话人管理 |
| WebSocket | `/ws/meeting/{meeting_id}` | 默认实时转写 |
| WebSocket | `/ws/meeting/{meeting_id}/hybrid` | FunASR + Qwen 混合链路 |
| WebSocket | `/ws/meeting/{meeting_id}/qwen` | Qwen ASR 链路 |
| WebSocket | `/ws/meeting/{meeting_id}/whisper` | Whisper/FunASR 相关实验链路 |

完整契约参考 [api-contracts.md](./api-contracts.md)。

## 4. 企业化差距

当前系统已经能完成演示级闭环，但距离稳定企业交付还需要重点补齐以下内容。

### 4.1 实时性

企业实时字幕需要稳定低延迟。建议以 FunASR 为主链路，并把 Qwen 增强改为异步句段修正，不阻塞实时字幕。

目标指标建议：

- 首字延迟：1 秒以内
- 稳态字幕延迟：2 秒以内
- 句段修正延迟：允许 3 到 10 秒
- 会议结束后总结：进入后台任务，不阻塞页面

### 4.2 准确性

需要建立标准测试集，不只凭单次试听判断。建议准备：

- 普通话单人会议
- 多人讨论会议
- 带口音样本
- 有背景噪声样本
- 专业术语样本
- 长会议样本

评价指标：

- 字错误率
- 关键词召回率
- 专业术语准确率
- 说话人识别准确率
- 总结事实一致性

### 4.3 稳定性

会议是长连接场景，必须处理网络抖动、浏览器权限、音频设备异常、服务重启和模型队列阻塞。

建议补齐：

- WebSocket 自动重连
- 音频缓冲和断点续传
- 服务健康检查
- 后台任务队列
- GPU 占用监控
- 日志和错误码规范

### 4.4 安全与权限

企业场景需要考虑：

- 登录认证
- 会议级权限
- 录音和转写数据隔离
- 操作审计
- 敏感信息脱敏
- 导出文档权限控制

## 5. 推荐优化路线

1. 固化混合 ASR：FunASR 输出实时字幕，Qwen 只做句段修正和会后增强。
2. 总结任务异步化：增加任务状态、阶段进度、取消和重试。
3. 说话人闭环：允许人工修正说话人，并保存为后续声纹训练数据。
4. 建立测试集：用固定音频持续回归三种 ASR 模式和总结质量。
5. 前端状态统一：把录音、转写、修正、总结、导出拆成清晰状态机。
6. 企业部署整理：端口、日志、模型、数据目录、环境变量全部配置化。

## 6. 当前限制

- 本地大模型总结速度受显存、队列和上下文长度影响。
- 说话人识别仍需要更多真实多人会议验证。
- Qwen 增强如果直接覆盖 FunASR 文本，可能出现信息删减，需要保留原始文本并做差异对照。
- 部分历史实验链路仍保留在代码中，后续应进一步收敛到推荐链路。
- 会议侧与老记仍共用同一个前端工程，后续可以继续拆分发布包。
